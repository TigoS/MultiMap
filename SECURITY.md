# Security Policy

## Supported Versions

Security fixes are provided for the latest supported release line. Older release lines are evaluated case by case and may require an upgrade before a fix can be delivered.

| Version | Supported          |
| ------- | ------------------ |
| 3.2.x   | :white_check_mark: |
| 3.1.x   | :x:                |
| 3.0.x   | :x:                |
| < 3.0   | :x:                |

## Reporting a Vulnerability

Please do not report security vulnerabilities in a public GitHub Issue.

Report vulnerabilities privately through GitHub's private vulnerability reporting feature:

- <https://github.com/TigoS/MultiMap/security/advisories/new>

Include as much of the following as possible:

- A description of the issue and potential impact
- Affected package or source version
- Target framework and operating environment
- Minimal reproduction steps or proof of concept
- Suggested mitigation or fix, if known
- Whether the report contains information that should remain confidential

You can expect an initial acknowledgment within 5 business days. The maintainer will investigate the report, request additional information when needed, and keep the reporter informed as the investigation progresses.

A report may be accepted and scheduled for a private fix and coordinated disclosure, or declined if it is not reproducible, is outside scope, or is determined not to be a vulnerability. When possible, the maintainer will explain the decision and provide remediation or upgrade guidance.

Please give the maintainer a reasonable opportunity to develop and release a fix before public disclosure. MultiMap is licensed under the MIT License and is provided without a guarantee of a security-response service level.
